Create an MQTT user (the broker reads from Postgres via the operator):
  cat <<EOF | kubectl apply -f -
  apiVersion: pgmqtt.io/v1alpha1
  kind: User
  metadata:
    name: ha
    namespace: {{ .Release.Namespace }}
  EOF
  # The reconciler creates a Secret <name>-mqtt-credentials with
  # username/password/host/port/uri keys. Wire it into your app.

{{- if not .Values.networkPolicy.enabled }}

⚠  NetworkPolicy is OFF.
   The chart's ClusterRole lets the broker ServiceAccount read, create
   and overwrite Secrets in every namespace (the operator writes each
   User's credentials Secret next to the User and reads its
   passwordSecretRef). Code execution in a broker pod gets the same
   access. A NetworkPolicy does not take that access away; it limits
   what else such a pod can reach and where it can send what it reads.

   For homelab/production: enable networkPolicy with `egress.postgres`
   pinned to your CNPG/postgres-operator selector before exposing the
   broker outside its VLAN.
{{- end }}

{{- if and .Values.networkPolicy.enabled (not .Values.networkPolicy.egress.postgres) }}

ℹ  networkPolicy.egress.postgres is empty, so the policy allows egress
   to any destination on TCP {{ .Values.networkPolicy.egress.postgresPort }}.
   Pin it to your Postgres pods or CIDR.
{{- end }}

{{- if and .Values.networkPolicy.enabled (not .Values.networkPolicy.egress.kubernetesAPI) }}

⚠  networkPolicy.egress.kubernetesAPI is empty.
   The fallback rule selects API server pods by label. Most network
   plugins do not match a host-network API server that way; if the
   operator logs API timeouts and Users stay unreconciled, set it:
     --set 'networkPolicy.egress.kubernetesAPI[0].ipBlock.cidr=<api-server-ip>/32'
{{- end }}

{{- if and (not .Values.database.url) (not .Values.database.existingSecret) }}

⚠  database.url AND database.existingSecret are both empty.
   The broker won't start. Set one of:
     --set database.url='postgres://USER:PASS@HOST/DB'
     --set database.existingSecret=<name-of-secret-with-uri-key>
   The default key is "uri" (matches CNPG's <cluster>-app Secret);
   override database.existingSecretKey if your Secret uses a different
   key name.
{{- end }}

{{- if and .Values.serviceMonitor.enabled (not .Values.serviceMonitor.labels) }}

ℹ  serviceMonitor.enabled=true but serviceMonitor.labels is empty.
   Many prometheus-operator installs filter ServiceMonitors by a
   release label (e.g. `release: prometheus`). If your scrape never
   appears, set:
     --set serviceMonitor.labels.release=prometheus
{{- end }}

{{- if and .Values.tests.enabled .Values.listeners.tcp.enabled }}

ℹ  `helm test` runs a mosquitto Pod that reads MQTT credentials from the
   Secret `{{ .Values.tests.credentialsSecret }}` in this namespace.
   Create it BEFORE running `helm test`: a User CR named `<name>` gets
   the Secret `<name>-mqtt-credentials`.
{{- end }}

For ops, see the README and the sizing-matrix comment in values.yaml
above `resources:`. Front the broker with an L4/L7 TLS terminator for
mqtts://1883 / wss://8083 — pgmqttd doesn't terminate TLS itself.
